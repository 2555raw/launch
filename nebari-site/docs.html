How Nebari works.

Three small contracts, no owner, no upgrade path. This page is the whole spec.

Overview

Nebari is a launchpad on Robinhood Chain (chain id 4663). A launch is one transaction that creates a token with a fixed supply of one billion, initialises a Uniswap v4 pool between that token and the asset you chose, and deposits the whole supply as single-sided liquidity from the start price upwards. The factory keeps the position and has no function to remove it, so the liquidity is locked for as long as the chain exists.

Because the whole supply sits above the start price and nothing sits below it, the start price is a floor: the pool cannot quote lower than the tick it was initialised on.

Fees

Every pool charges a 1% swap fee. Anyone can call collectFees(token) on the factory at any time. The fees earned in the pair asset are split:

Holders50%, credited in proportion to the tokens held at the time of collection. Each holder claims from the token contract; the pool and the factory never earn.
CreatorThe remainder after the protocol share, sent immediately.
Protocol10%, set once when the factory is deployed and sent to the treasury address.

Fees earned in the token itself are burned, which is why the supply on a token page only ever goes down. If nobody holds the token yet when fees are collected, the holders' half goes to the creator instead of being lost.

Contracts

  • NebariFactory: launches tokens, owns every pool position, collects and splits fees. Immutable: no owner, no pause, no upgrade.
  • NebariToken: a plain ERC20 with burn, plus dividend accounting in the pair asset (claimable, claim).
  • NebariRouter: exact-input swaps against the Uniswap v4 PoolManager, and a quote that simulates the swap. The trade box on each token page uses it.

Source, compile script and the end-to-end test against the real PoolManager are in contracts/ of the repository.

Deploy your own

The contracts are deployed with a private key you control. Nothing in this site ever asks for it.

cd nebari-site/contracts
npm install
npm run compile
npm test                       # end-to-end against the real PoolManager, locally

# fund the deployer with a little ETH on Robinhood Chain, then:
PRIVATE_KEY=0x… TREASURY=0x… PROTOCOL_BPS=1000 npm run deploy -- --write

--write pastes the new factory and router addresses into config.js. Commit that and publish the folder on any static host. The PoolManager address in config.js must be the official Uniswap v4 deployment for chain 4663; check it on the Uniswap deployments page before you deploy.

What can go wrong

  • Tokens are not securities and do not track the asset they pair with. A token rooted to TSLA gives you no claim on Tesla.
  • Robinhood stock tokens may carry transfer restrictions. If a pair asset refuses to move to the token contract, the fee split for that pool reverts until it can. Test with a small amount first.
  • The contracts are immutable. There is nobody who can fix a mistake in a launch after the fact, including the start price.
  • The volume figure on each page is derived from the fees the pool has earned, not from an indexer; it is an estimate.
