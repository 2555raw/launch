How it works

Three calls between your agent and the money

No shared cards, no keys pasted into a prompt. One credential per agent, a policy that bounds it, and a record that proves it.

01

Issue the credential

Every agent gets its own identity and key pair. Revoke it in one click; its history outlives the revocation. POST /v1/agents

02

Write the policy

Daily ceiling, allowed payees, a maximum per operation, and a threshold above which a human has to sign off. POST /v1/policies

03

Let it pay

The agent asks for authorization, Nomia answers in milliseconds and settles on whichever rail fits: stablecoin, transfer or virtual card. POST /v1/authorizations

Product

What it takes to hand a machine the budget

Control before the payment, traceability after it. Both halves in the same API.

Identity per agent

A signed credential for each agent, not one team key passed around. You know who spent without inferring it from a log.

Spend policies

Ceilings by day, by payee and by operation. What goes over the line isn't declined in silence: it waits for someone to approve it.

Per-call micropayments

From a tenth of a cent. Charge per response, per token or per finished task, and batch the settlement when it pays to.

Multi‑rail settlement

Stablecoin, instant transfer or a single-use virtual card. The agent asks for a payment; the policy picks the rail.

Auditable record

Every authorization stores who, how much, to whom and on what grounds, hash-chained and exportable to your ERP.

Kill switch

Catches spend loops and unfamiliar payees, and cuts off the whole agent with a single call when something runs away.

import { Nomia } from "@nomia/sdk";

const nomia = new Nomia(process.env.NOMIA_KEY);

// a credential and a daily ceiling for this agent
const agent = await nomia.agents.create({
  name:   "market-researcher",
  policy: { daily: 5000, perCall: 500, currency: "USDC" }
});

// the agent pays for a data call
const payment = await nomia.pay({
  agent:  agent.id,
  payee:  "vendor_maps_api",
  amount: 2400,
  reason: "geocoding batch"
});

console.log(payment.status, payment.settledIn); // approved 1.9s

FAQ

What everyone asks before signing

What if the agent goes haywire and overspends?

It can't. The policy is evaluated before every authorization, not after: a ceiling per operation, a ceiling per day, and an allow-list of payees. Anything outside that range waits for human approval, and the loop detector cuts off the whole agent if it repeats the same payment without making progress.

Do you custody the money?

No. Nomia is the authorization and record plane; the funds sit in your account or your wallet and settle through regulated entities and contracts you already have. We decide whether the payment goes out, and we leave the proof of why.

How long does the integration take?

An afternoon. Install the SDK, create an agent with its policy, and run your first authorization in test mode. If your agent already speaks MCP, add the server to its config and pay shows up among its tools.

What if the vendor doesn't take stablecoins?

The policy picks the rail. The agent asks for a payment and Nomia settles it in USDC, by instant transfer, or with a single-use virtual card, depending on what the payee accepts. The agent doesn't change a line of code.

How do I defend this in an audit?

Every authorization stores the agent, the amount, the payee, the policy applied and the stated reason, chained by hash. Export it to CSV or straight into your ERP, and every settled payment carries a signed receipt.

Does it work with agents that aren't mine?

Yes. You can issue scoped credentials to third-party agents, each with its own ceiling and its own list of payees, and revoke them without touching the rest of the fleet.
