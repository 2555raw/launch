RENTA

一个持有出租公寓份额的金库，公布每一套公寓付了多少钱， 并让你自己核对算术。

租客交租。账单从中扣除。剩下的留在金库里，推高份额价格。 你永远不会收到租金转账，也永远不会拥有一套公寓。

每月一号，金库发布月报（The Roll）——刚结束那个月的报告。它列出每一套公寓、 租约上写的金额、租金是否到账，以及扣除的每一项成本。文件会被哈希，哈希与当月的 结算份额价格一起写在链上，因此你读到的文件可以被证明就是发布的那份文件。

本文档涵盖三件事：

  • 使用金库——份额是什么，它的价格如何变动，费用是什么，以及可能出什么问题。
  • 月报——如何阅读月报，以及如何自己验证一份月报。
  • 在其上构建——合约、链、审计，以及如何在自己的机器上运行整个系统。

它如何运作

金库是一家控股公司，前面放着一个代币。这家公司——一家荷兰 B.V.——全款持有 六个国家八座城市的十栋公寓楼，并持有一笔 EURG 现金储备。代币 vRENTA 是对这一切 按比例的权利主张。

每个月，依次发生三件事：

  1. 收租。各城市的管理机构从七十七套公寓收取租金，扣除自己的费用后转入金库的运营账户。
  2. 付账单。维修、房产税、保险、管理机构和审计师的费用从该账户支出。剩下的即为留存。
  3. 写入结算。每月最后一天，留存金额计入金库持有量，计算新的份额价格，并发布月报，其哈希写在链上。

这个结构里没有任何借贷。任何楼宇都没有房贷，金库没有信用额度，代币没有杠杆。 金库以存款和留存租金的速度增长，比银行允许的要慢，而这正是重点。

什么决定份额价格

一个 vRENTA 的价格，是金库的持有量除以流通份额数。金库的持有量是两项之和： 储备中的 EURG，以及按买入价计的楼宇，后者只在楼宇出售或委托独立估值时调整—— 估值每年一次，估值本身也会公布。

由于两次估值之间楼宇按成本入账，价格在两次结算之间只因两个原因变动：

  • 留存租金。当月实收租金减去当月成本，计入储备。
  • 曲线税。存入后九十天内赎回的人，以略低于份额价格的价格卖出。差额留在储备中归其他人所有。见费用。

存入与赎回

金库是一个 ERC-4626 合约，所以它的运作方式和其他合约一样。你授权 EURG， 调用 deposit，vRENTA 在同一笔交易中按该区块时的份额价格到账。 最低 100 EURG。没有上限，没有白名单，没有锁定期。

离开时，你带上份额数量调用 redeem。只要储备够付，EURG 在同一个区块到账—— 储备大致保持在一个月租金加上通常的赎回量，上次结算时为 €430,593。 超过储备的赎回会排队，在下一次结算时按那次结算的价格清算。这是唯一需要等待的情况， 月报会记录每一笔排队的赎回及其清算日期。

你永远不会收到租金。没有流式支付、空投或可领取的东西。租金在价格里。如果你想让它进钱包，就赎回你持仓中价值相当的那一部分。

费用

存入0.00%
赎回0.00%
曲线税适用于最近一次存入后 90 天内的赎回，从第一天的 3.0% 直线下降到第九十天的 0.0%。这不是我们收取的费用：它留在金库里，推高留下来的持有人的价格。
管理费每年为金库持有量的 0.35%，每月在结算前从租金中扣除。它包含在上面 €18,250 的成本里，并且是每份月报中的一行。
业绩费无。

曲线税的存在，是为了让一个紧张的星期不至于迫使金库卖掉一栋楼，去付钱给三周前才进来的人。 楼宇要几个月才能卖掉，而且急着卖会卖得很差；这项税让提前离开的代价， 大致等于一次仓促出售会让其他所有人付出的代价。

可能出什么问题

房产是慢的，也并非没有风险。大致按你应该担心的顺序：

  • 租客不交租。管理机构追讨，月报记为应收未收，当月价格涨幅变小。在七十七套公寓里，一套空置每月只损失几百欧元，而不是全部。
  • 一次大修。屋顶、锅炉、外墙。2026 年 5 月就有一次：Kurt-Eisner-Straße 花了 €4,180，一次付清，从当月租金里出。那个月价格照样上涨，只是少了一点。
  • 估值下跌。楼宇每年独立重估一次。如果某个市场跌了，份额价格在那次结算时随之下跌。除了赎回队列以低于储备的价格清算之外，这是价格下跌的唯一途径。
  • 赎回队列。如果赎回超过储备，它们要等到下一次结算。极端情况下金库会卖掉一栋楼来应付，市场给什么价就是什么价，每个人的份额都要承担这一点。
  • 稳定币。金库持有 EURG。如果 EURG 的交易价格偏离一欧元，即使楼宇没有任何变化，储备按欧元计也会缩水。
  • 我们。运营金库的公司可能会停止。控股公司和楼宇不依赖它：vRENTA 持有人拥有控股公司，无论这个网站是否存在，金库合约都接受任何钱包的赎回，房契也在各国以常规方式登记。

阅读月报

一份月报是金库一个月的全部内容，装在一个文件里。它有四个部分，顺序永远如下：

  1. 头部。月份、期初和期末份额价格、期初和期末的流通份额数，以及上一份月报的哈希。
  2. 租金表本身。每套公寓一行：楼宇、单元、租约上应付的金额、到账金额和到账日，以及晚付、部分付或未付的备注。
  3. 成本。运营账户的每一笔支出，附所属楼宇、收款方、发票编号和金额。管理费在这里和其他项一样是一行。
  4. 资金变动。当月每一笔存入和赎回，按钱包列出，附成交价格和适用的曲线税。

大家最先看的两个数字是应收和实收。应收是租约上写的。实收是到账的。 两者的差距就是这个月的故事，租金表逐行讲述它。

验证月报

月报以纯文件形式发布，其 SHA-256 哈希由设置当月结算价格的同一笔交易写入金库合约。 验证一份月报： 

# 下载 2026 年 8 月的月报并计算哈希
curl -sO https://renta.example/rolls/2026-08.csv
sha256sum 2026-08.csv

# 读取登记合约为该次结算保存的哈希
cast call $REGISTRY "rollHash(uint256)(bytes32)" 202608 --rpc-url $RPC

# 两者应当一致。若不一致，你手里的文件不是发布的那份。

# 或者让脚本一次处理六份，顺便重算每一次结算
node scripts/recompute.js --check

发布文件的格式

每月一个 CSV，UTF-8，逗号分隔，带一个 section 列，取值为 header、rent、cost 或 movement 之一。 金额以 EURG 计，六位小数，无千位分隔符。日期为 ISO 8601。钱包地址带校验和。 除上一份月报的哈希外，文件中没有任何内容来自文件之外。

在本地运行

网站是纯 HTML、CSS 和 JavaScript，没有构建步骤。合约用 Foundry。 网站上的一切都由月报计算得出，所以只要月报在磁盘上，你不用碰链就能重现每一个数字。 

git clone https://github.com/renta-estate/vault
cd vault

# 网站
python3 -m http.server 8000        # http://localhost:8000/site

# 合约
forge build && forge test

# 从月报重算每一次结算
node scripts/recompute.js rolls/

合约

一共三个，而且刻意写得很小。

  • Vault。一个 ERC-4626，加了两样东西：redeem 上的曲线，它会查找调用者最近一次存入；以及一个只有运营方可以每月调用一次的 close 函数，它同时设置新价格和月报哈希。没有哈希就设不了价格，没有价格也设不了哈希。
  • 月报登记合约。一个从月份到哈希的映射，只能追加。一旦写入，某月的哈希任何人都改不了，包括我们。
  • 运营方。一个三取二多签，拥有调用 close 的权利。它无权把 EURG 转出金库；只有 redeem 能做到，而且只能转给赎回的钱包。

源代码在仓库里，在区块浏览器上已验证，并且不可升级。如果将来需要改动，那会是一个新金库， 在月报中公布，并提供一个由你自行选择是否参与的迁移。

审计

有两样东西被审计，由两个不同的人来做。合约在部署前由一家独立的智能合约公司审阅， 报告在仓库里，附每一项发现及其处理。公司的账目——楼宇、租金、银行余额——每年由一位 注册的荷兰审计师审计，经审计的账目随十二月的月报一起发布。月报的作用是让第二项审计 变得无聊：审计师到来时，十二个月的账本早已公开并哈希过了。

谁可以投资

vRENTA 面向居住在欧盟和欧洲经济区、瑞士和英国、年满 18 岁并通过身份验证的人发售。 不面向美国、加拿大或日本的居民或公民，不面向任何需要公司尚未持有的牌照的地方， 也不面向欧盟制裁名单上的任何人。名单在 config.js 里，也在连接钱包前 看到的那道门上。

身份验证由受监管的服务商执行，在你第一次存入前进行一次。金库合约本身不知道你是谁—— 它只认识一个钱包——公司依照欧盟数据保护法保存两者之间的关联，保存期限以反洗钱规则 要求为限，不会更长。

这是什么，不是什么

vRENTA 是一家持有楼宇的公司的份额。在大多数地方这使它成为一种证券，它也是作为证券发售的。 它不是存款，没有保险，价格可能下跌。租金可能停止到账。一栋楼明年可能比今年更不值钱。 过去的结算是记录，不是承诺。

本网站和本文档中的任何内容都不是建议。如果你不会仅凭一家小型房产公司公布的账目去买它的股份， 也不要仅凭一份月报来买这个。

这是一个演示版本。本网站上的每一个地址、每一栋楼和每一次结算都是虚构的，用来展示这套机制读起来是什么样。背后没有已部署的合约，也没有公司。
